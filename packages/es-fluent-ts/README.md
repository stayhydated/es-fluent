# `@es-fluent/core`

Framework-neutral TypeScript runtime for contracts generated by
`cargo es-fluent export typescript`. It uses `@fluent/bundle` and
`@fluent/langneg` through an environment-neutral API that works across browser,
Node, SSR, and JavaScript-native hosts.

Create one runtime around the generated manifest and embedded resource loader.
Replace the loader with lazy `import()` or network loading when an application
wants locale chunks. Create an `EsFluentRequest` for each SSR request or
independent UI root:

~~~ts
import { loadResource, manifest, messages } from "./generated/index.js";

const runtime = createEsFluentRuntime({ manifest, loadResource });
const i18n = await runtime.createRequest(["fr-CA", "fr"]);
const title = i18n.format(messages.app.app.title);
~~~

Bundles are cached by package, locale, and domain. Locale choices remain on the
request object. `snapshot()` and `runtime.hydrate()` transfer deterministic
locale chains across SSR hydration and verify the generated content revision.

See the repository book's **TypeScript, React, and SolidStart** chapter for Vite,
SSR, and resource-loading examples. The runnable
[`examples/typescript-example`](../../examples/typescript-example) app defines
its contract in Rust and hosts the generated browser demo on the project site.
